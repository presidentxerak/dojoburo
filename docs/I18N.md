# Traduire Dojoburo

Demandes :
- « mets en place la traduction en fonction de la langue du user (français, anglais, espagnol, italien, allemand, portugais, japonais etc...) » ;
- « fais toutes les traductions et faudra le faire pour tous les nouveaux cours ».

## Comment c'est construit

- **Français et anglais** sont écrits dans le code, côte à côte : `B('english', 'français')` et le dictionnaire `src/i18n/dict.ts`.
- **Espagnol, italien, allemand, portugais, japonais** viennent de catalogues JSON qui associent à chaque texte **anglais** sa traduction :
  - interface : `src/i18n/locales/<code>.json` (chargé avec la langue) ;
  - cours : `src/i18n/locales/content/<code>.json` (chargé à l'ouverture d'une leçon ou de la bibliothèque).
- Un texte absent d'un catalogue s'affiche en anglais, jamais vide.

## Après avoir ajouté ou modifié un cours (OBLIGATOIRE)

1. `node scripts/i18n-extract.mjs` : met à jour `src/i18n/source-ui.json` et `src/i18n/source-content.json`.
2. Pour chaque langue, lister ce qui manque :
   `node scripts/i18n-missing.mjs <code> content` (et `ui`).
   Le script écrit `node_modules/.i18n-parts/todo-<kind>-<code>.json` : les indices et les textes anglais à traduire.
3. Traduire ces textes (règles ci-dessous) dans un lot `node_modules/.i18n-parts/content-<code>/<nom>.json` au format `{ "indices": [...], "items": [...] }` (même ordre que le fichier « todo »), vérifier avec `node scripts/i18n-part-check.mjs <lot> content`.
4. Fusionner : `node scripts/i18n-merge.mjs <code> content`, puis `node scripts/i18n-check.mjs --content`.
5. `npm test` refuse un catalogue sous 99 % : un nouveau cours non traduit ne passe pas.

## Règles de traduction

- Traduire depuis l'**anglais** ; le français sert de contexte pour lever une ambiguïté.
- Registre poli et pédagogique : espagnol (usted), italien (Lei), allemand (Sie), portugais du Brésil (você), japonais (です・ます調).
- Garder **tels quels** : les noms de marque et de produit (Dojoburo, Dojobot, Pass Dojoburo, Claude, Claude Code, ChatGPT, Lovable, Supabase, Vercel, GitHub, Stripe...) ; le jargon IA usuel (prompt, token, agent, workflow, LLM, API, RAG) ; en japonais, les katakana usuels sont admis (プロンプト, トークン, エージェント).
- Garder **à l'identique** : le code, les commandes, les noms de fichiers et de variables, les URL, les adresses e-mail, tout ce qui est entre accents graves (`...`), les marqueurs `{n}`, `{p}`, les nombres, les prix, les symboles « → », « · », « × », et les retours à la ligne.
- **Jamais** de tiret cadratin ni demi-cadratin comme ponctuation, **jamais** d'emoji ni de caractère pictographique.
- Lexique du jeu : temple (es templo, it tempio, de Tempel, pt templo, ja 寺院), étage (piso, piano, Etage, andar, 階), maître (maestro, maestro, Meister, mestre, 師範), badge (insignia, distintivo, Abzeichen, insígnia, バッジ), ceinture (cinturón, cintura, Gürtel, faixa, 帯), leçon (lección, lezione, Lektion, lição, レッスン), mission (misión, missione, Mission, missão, クエスト).
- Traduire fidèlement, sans rien ajouter ni retrancher.
